01 · Organization

One cart, several layers

The angry.p8 file contains the Lua code and the game's visual data. The __lua__, __gfx__, __map__, __sfx__, and __music__ sections make up the project.

01

Game manager

Variables such as initial, game_over, points, and timer control the global state.

02

Entities

The game creates Lua objects with methods such as _init, _update, and _draw.

03

Visual data

Sprites, map, sounds, and music are stored in the cart and accessed by the runtime.

04

Web export

PICO-8 turns the cart into HTML with a canvas, JavaScript runtime, and browser controls.

02 · Main loop

The game runs through three functions

PICO-8 calls these functions automatically. The project uses the cycle to start, update, and draw the game.

1

_init() calls start_game() and creates the character, clouds, and obstacles.

2

_update() advances time, updates entities, and tests boundaries and collisions.

3

_draw() clears the screen and draws scenery, character, obstacles, and score.

4

_reset() repositions everything and resets the score after defeat.

03 · Character

Impulse against gravity

The create() function acts as a simple constructor. It returns a table containing the character's state and behavior.

PHYSICS

y_move -= 7/30

Vertical speed continuously decreases, simulating gravity.

→
INPUT

y_move = 2

Pressing up applies a new impulse.

04 · Obstacles and score

The gap is a rule, not an image

Each obstacle has a horizontal position, gap height, and passage state. The column is drawn in 8-pixel blocks.

01

Spawn

create_obstacle(2) creates obstacles every 60 pixels, starting outside the player's immediate area.

02

Random gap

position = flr(rnd() * 10 + 3) chooses the vertical position of the open space.

03

Collision

check_position(x,y) checks whether the player is within the horizontal range and outside the gap.

04

Score

When the player passes the obstacle, points increases once and the high score is updated.

05 · Scenery

Objects that breathe in the background

The cloud manager creates two cloud scales. Each object moves left and reappears on the right after leaving the screen.

CREATEcloud_manager(qtde, grandes)
UPDATEself.x -= 1
RESPAWNself.x = 130 / 150
